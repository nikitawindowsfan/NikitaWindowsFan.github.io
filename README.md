# NikitaWindowsFan — развертывание функций Firebase

Фронтенд остаётся статическим сайтом на GitHub Pages. Общие данные сайта и новые сообщения хранятся в Firebase Firestore, фотографии — в Firebase Storage; файлы посетителей на компьютер не записываются. Переключатель тестового плеера — персональная настройка администратора в `localStorage`, поэтому она переживает перезагрузку страницы на этом устройстве.

## Однократная настройка Firebase

1. В Firebase Console для проекта `nikitawindowsfan` включите **Authentication → Sign-in method → Email/Password** и **Anonymous**. Создайте пользователя администратора.
2. В **Authentication → Settings → Authorized domains** проверьте, что добавлен `nikitawindowsfan.github.io` (и домен, с которого вы будете проверять сайт).
3. Создайте Firestore Database и включите Firebase Storage, если они ещё не созданы.
4. Замените `nikita@nikitawindowsfan.local` на реальный email администратора **в трёх местах**: `index.html` (`ADMIN_EMAIL`), `firestore.rules` и `storage.rules`. Email должен совпадать буквально.
5. Установите Firebase CLI и войдите в него с учётной записью владельца Firebase-проекта. Из корня репозитория выполните:

   ```sh
   firebase deploy --only firestore:rules,storage,functions
   ```

   Cloud Functions могут потребовать подключить для проекта тариф Firebase Blaze (оплата по фактическому использованию). Перед публикацией проверьте лимиты и настройки биллинга в Firebase Console.

Если шестерёнка админки скрыта на новом устройстве, откройте консоль разработчика страницы и выполните `window.admin()`, затем войдите в админку. После первого успешного входа кнопка сохранится на этом устройстве.

После развёртывания публикации из админки будут записываться в документ `public/site`, загруженные фото — в `site-images/` в Storage. Правила разрешают изменять эти данные только администратору. Чат загружает последние 50 сообщений в реальном времени; отправка идёт через Cloud Function, а прямые записи из браузера правилами запрещены.

## Фильтры и временные блокировки чата

Функция `sendChatMessage` на сервере блокирует распространённые русские и английские ругательства, URL и домены. За первое нарушение выдаётся блокировка на 10 минут, за повторные нарушения в течение 30 дней — на 1 час и затем на 24 часа. Между обычными сообщениями также установлен короткий интервал против спама. Список слов и длительности настраиваются в `functions/moderation.js` и `functions/index.js`.

Блокировка привязана к Firebase Anonymous Auth UID браузера. Это серверная блокировка, а не только проверка интерфейса; однако анонимный посетитель может попытаться получить новый UID, поэтому для публичного чата дополнительно рекомендуется включить Firebase App Check и следить за квотами проекта.

Проверки фильтров можно запустить локально без Firebase:

```sh
npm test --prefix functions
```

## Хранение видеозаписи эфира

Тестовый плеер уже обращается к удалённому Playback API (`PLAYBACK_BASE`) и не сохраняет видео на компьютере зрителя. Запись эфира и срок её хранения задаются на сервере MediaMTX параметрами в его `mediamtx.yml` (в частности, `recordPath` и `recordDeleteAfter`). Конфигурации этого отдельного сервера в репозитории нет, поэтому изменить срок хранения записи эфира одним изменением GitHub Pages невозможно.
